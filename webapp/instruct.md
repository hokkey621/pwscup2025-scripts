
# SecHack365 医療AI利活用基盤 デモMVP 要件定義書

## 1. 概要と目的

### 1.1. プロジェクト背景
本プロジェクトは、SecHack365の研究駆動コースにおいて、「医療AIの利活用のための暗号化通信と匿名化技術」を開発するものである。現状の医療現場では、機微な医療データを手動（HDD運搬など）で研究機関に送付しており、多大な「手間」と「セキュリティリスク」（例：ランサムウェアによる情報漏洩）が発生している。

### 1.2. 本アプリの目的
本Webアプリケーションは、SecHack365対面会でのデモンストレーションを目的とした **MVP (Minimum Viable Product)** である。
以下の価値を、MacBook 1台で完結するWebアプリとして視覚的に実証する。

1.  **ビフォー・アフターの可視化:** 医師（非技術者）が入力した生の医療データ（Bi）が、選択したアルゴリズムによって即座に匿名化データ（Ci）に変換されるプロセスを示す。
2.  **アルゴリズムの比較・議論:** 異なる匿名化手法（例：ナイーブな手法 vs 独自開発の手法）が、PWS CUP 2025の評価軸（有用性・匿名性） にどのような異なる影響を与えるかをリアルタイムで提示し、議論の材料を提供する。
3.  **MIA（メンバーシップ推定攻撃）の脅威のデモ:** 「デモ中に入力した特異なデータ」が、ナイーブな加工では攻撃者に特定（推定）されてしまい、本命の手法では防御できることを示す。

## 2. システム構成

| 項目 | 要件 |
| :--- | :--- |
| **言語** | Python 3.10以降 |
| **仮想環境** | `uv` （リポジトリルートの `pyproject.toml` に依存関係を追加して使用） |
| **Webフレームワーク** | `streamlit` |
| **実行環境** | MacBook 1台でスタンドアロン動作 |
| **ディレクトリ構造** | 全ての新規コードは `webapp/` ディレクトリ配下にのみ配置する。<br> `template/` やリポジトリルートの他ファイルは**一切変更しない**。 |
| **主要ファイル** | `webapp/app.py`: Streamlitのメインアプリ<br> `webapp/anonymize.py`: 匿名化ロジック<br> `webapp/evaluate.py`: 評価スクリプトの呼び出しラッパー<br> `webapp/outputs/`: （`.gitignore`対象）Ci, Bi', モデル等の一時保存先 |

## 3. データ要件

1.  **ベースBi（元データ）:** PWS CUP 2025のスキーマに準拠したCSV（例: `data/HI_10K.csv`）をアプリ起動時に読み込む。
2.  **新規入力データ:** ペイン1のフォームから入力される**1行**のデータ。
3.  **Bi'（評価対象Bi）:** 「ベースBi」に「新規入力データ」を**動的に結合（Concat）**したもの。
4.  **Ci（評価対象Ci）:** 「Bi'」を「FR-4」で指定されたアルゴリズムで加工したもの。
5.  **PWS CUP 評価データ:** `template` 配下のスクリプト群が利用するデータ（`data/HI_100K.csv` (Ai), `data/HI_ans.csv` (ans)）を、`evaluate.py`から`subprocess`経由で参照する。

## 4. 機能要件

### FR-1: 2ビュー構成 (`app.py`)
- 画面上部に `カルテ入力 / 匿名化結果` の2ボタンを表示し、`st.session_state.current_view` でビューを切り替える。
- **カルテ入力ビュー:** 実際の電子カルテを模したシングルページ構成。入力に集中できるよう他ペインは表示しない。
- **匿名化結果ビュー:** 実行履歴をタブで切り替え、各手法の差分と評価を閲覧できる。

### FR-2: カルテ入力ビュー
1. **入力フォーム:** Bi スキーマに対応したフィールドを「プロフィール / 受診歴 / 既往歴 / バイタル / その他」のセクションに分けて自動生成する。
    - 数値列は `st.number_input`、カテゴリ列は `st.selectbox`、バイナリ列は `st.toggle` を用い、代表値で初期化する。
2. **アルゴリズム選択:** `anonymize.ALGORITHM_OPTIONS` を `st.radio` で表示し、説明文を添える。
3. **実行ボタン:**
    - `[ 1. 匿名化実行 ]`：選択アルゴリズムのみで処理する。
    - `[ 1. 全手法で匿名化 ]`：登録済み全アルゴリズム（現在は4種：A/B/C/D）を順番に実行し、Run履歴へ保存する。
4. **入力リセット:** `入力を初期値に戻す` ボタンでフォームを初期化する。

### FR-3: 匿名化処理 (`anonymize.py`)
1. **トリガー:** FR-2の各実行ボタン。
2. **処理:** 
    a. ベースBiにフォーム入力を連結し、行数10,000を維持した `Bi'` を作成。  
    b. アルゴリズムIDごとに `Ci` を生成。  
    * `naive`：Bi'をそのままコピー。  
    * `main`：非バイナリ数値列にのみノイズを加算。  
    * `k_anonymity`：k=2 のマイクロアグリゲーション（`experiments/method_k_anonymity_k02` の設定）。  
    * `t_outlier_kmeans`：t分布で外れ値を検出し、tail_ratio=0.05・max_clusters=3でk-means代表値に置換。
3. **Run履歴:** それぞれ `RunRecord` として `st.session_state.run_history` に追記し、ラベル（例：`Run 3: アルゴリズムB`）を付与する。最新Runを結果ビューのデフォルト表示にする。

### FR-4: 匿名化差分ビュー（結果タブ内）
1. **タブ構成:** Run履歴ごとに `st.tabs` を生成し、タブ内で以下を表示する。
2. **差分表:** Runの `Bi'` と `Ci` の新規行のみを比較し、各列の `Bi'`, `Ci`, 差分を一覧化する。
    - 変更があった行は背景色でハイライトし、 `st.metric` で変更列数 / 総列数を表示する。

### FR-5: 評価ビュー（結果タブ内）
1. **個別評価ボタン:** 各タブに `[ 2. スコア計算実行 ]` を配置し、Run単位で評価を実施できる。
2. **一括評価:** 結果ビュー上部の `[ 2. 全手法の評価を実行 ]` で履歴全体をまとめて評価し、完了後にリロードする。
3. **評価結果:** `有用性/匿名性/Di精度/MIA結果` を `st.metric` 等で表示し、実行ログは `st.expander` に格納する。
4. **評価指標の説明:** 各タブ内で `U = 1 - Δloss`、`P = 1 - A`、`Acc_Di = (TP+TN)/(TP+TN+FP+FN)` のように数式付きで解説を表示し、Runごとのミニサマリ表を添える。

### FR-6: 評価処理 (`evaluate.py`)
1.  **トリガー:** FR-5の `[ 2. スコア計算実行 ]` ボタン押下時。
2.  **前提:** `st.session_state` から `Bi'` と `Ci` を取得する。
3.  **一時ファイル保存:** `Bi'` と `Ci` を `webapp/outputs/` 配下に一時CSVファイルとして保存する。
4.  **PWS CUP 2025 評価実行:** `subprocess.run` と `uv run python ...` を使用し、**`template` ディレクトリ の評価スクリプト群を厳密に呼び出す**こと。評価方法はtemplateディレクトリの実装に準拠する
6.  **返り値:** `有用性スコア`、`匿名性スコア`、`個別MIA結果`（テキスト）を `app.py` に返す。

## 5. テスト・検証要件 (Acceptance Criteria)

本MVPの「成功」は、スコアの良し悪しではなく、**デモシナリオがエラーなく最後まで実行できること**（＝処理が回ること）で定義する。

1.  `uv run streamlit run webapp/app.py` でアプリが正常に起動すること。
2.  ペイン1で「特異なデータ」を入力し、`[ 1. 匿名化実行 ]` を押すと、ペイン2にCiデータがエラーなく表示されること。
3.  `[ 2. スコア計算実行 ]` を押すと、`evaluate.py` が `train_di.py`, `attack.py`, `check_ans.py` の呼び出しを**最後まで**完了し、ペイン3にダミーではない（何らかの計算結果に基づいた）3つの評価結果（有用性、匿名性、MIA結果）がエラーなく表示されること。
